# 像素勇者團：魔王城大作戰

一款給國小課堂使用的**即時合作競答遊戲**。全班學生一起答題，累積傷害與能量，
在時間內合力打倒大魔王。

- 老師端：建立題庫、開房、產生 QR Code、投影魔王戰場、看結算報表
- 學生端：掃 QR Code → 輸入座號姓名 → 建立角色 → 答題打王

> 完整設計請見規劃書：`C:\Users\user\.opencode\plan\像素勇者團_魔王城大作戰_規劃書.md`

## 即時通訊：兩種模式

本專案把「即時通訊」抽成可替換的轉接層（`src/lib/realtime/`），
遊戲邏輯完全不需要知道底層用什麼服務。

| 模式 | 說明 | 使用時機 |
|---|---|---|
| **mock** | 用瀏覽器內建的 BroadcastChannel，同一個瀏覽器的多個分頁可互通 | 本機開發（預設） |
| **supabase** | 走 Supabase Realtime 雲端服務，學生手機可跨裝置連線 | 正式上課 |

### 怎麼測試？

1. `npm run dev`
2. 開啟 http://localhost:5180/dev/realtime
3. 在**另一個分頁**再開一次同一個網址
4. 兩邊輸入**相同房間代碼**、不同名稱，按「加入房間」
5. 應該會互相看到對方出現在成員清單，且能互傳訊息

這代表即時通訊層正常運作（不需要任何帳號）。

## 試玩大廳流程（M1）

不需要任何帳號，用同一個瀏覽器的多個分頁就能完整試玩：

1. `npm run dev`，開啟 http://localhost:5180/teacher
2. 點「開新遊戲」，填班級名稱、選魔王難度、貼上名單（例如 `1 王小明`、`2 陳小美`）
3. 按「建立遊戲並產生 QR Code」→ 進入房間頁，看到 QR Code 與房間代碼
4. **另開分頁**，輸入房間頁上的網址（例如 `http://localhost:5180/join/XXXX`）
5. 輸入座號與姓名 → 選角色 → 就會回到老師端的名單上

可以試試這些情境：

- 用**已有人使用的座號**加入 → 會被擋下
- 用**不在名單上的座號**加入 → 會被擋下
- 切到別的分頁 / 別的 APP → 老師端會顯示「🟡 不在分頁」
- 關掉學生分頁 → 老師端顯示「⚫ 離線」
- 老師端按「踢除」→ 學生端會顯示被移出

## 戰鬥玩法（M2）

1. 老師端按「開始遊戲」→ 畫面切成**魔王戰場**（投影給全班看）
2. 學生端自動切成**答題畫面**：題目 + 四個大按鈕
3. 答對 → 對魔王造成傷害（難度越高傷害越大、連擊有加成）
4. 答錯 → 個人 2.5 秒冷卻後換下一題，不影響團隊
5. 魔王依難度每隔 10～14 秒攻擊一次，扣團隊血條（有護盾時先扣護盾）
6. **勝利**：魔王 HP 歸零　**失敗**：團隊血條歸零或時間到

## 題庫管理（M3）

老師端 →「管理題庫」（網址 `/teacher/bank`）

- **新增／編輯／刪除題目**：科目、單元、難度（簡單／中等／困難）、題目、四個選項、正解、圖片、解析
- **題目列表**：可用科目／難度篩選，也能用關鍵字搜尋
- **匯入 CSV**：可先按「下載範本」照著填。欄位為
  `科目, 單元, 難度, 題目, 選項A, 選項B, 選項C, 選項D, 正解(A~D), 圖片網址, 解析`
  匯入時會**自動跳過重複的題目**，格式錯誤的列會列出原因
- **匯出 CSV**：加上 UTF-8 BOM，Excel 直接開不會亂碼
- **匯出／匯入 JSON**：完整備份（含圖片），換電腦時用這個搬題庫
- **圖片題**：可上傳本機圖片（自動壓縮成 640px 的 JPEG）或貼圖片網址

> 題庫存在這台電腦的瀏覽器（IndexedDB）裡。**建議定期「匯出 JSON」備份。**
> 題庫是空的時，戰鬥會自動使用內建的 18 題示範題。

## 團隊技能（M4）

全班答對題目會累積兩種能量，**滿了由老師按下按鈕釋放**（避免學生搶按）。

| 技能 | 效果 | 預設門檻（30 人） |
|---|---|---|
| 🛡 防禦 | 展開全隊護盾，魔王攻擊會**先被護盾吸收** | 450 點能量（約 45 秒） |
| 🔥 大招 | 對魔王造成大傷害，並讓魔王**暈眩 6 秒**（期間不攻擊） | 750 點能量（約 75 秒） |

- 護盾可吸收 200 點傷害（約 3 次魔王攻擊）
- 大招傷害 3000 點（約魔王總血量的 7.5%）
- 魔王暈眩時會顯示 😵 與倒數，學生端也會出現 💫 提示

### 傷害平衡（可調）

**隊伍血條固定 3000**，魔王攻擊力**不隨人數縮放**。
開新遊戲時可勾選「依人數自動調整魔王強度」，只縮放**魔王 HP、能量門檻與大招傷害**：

```
平衡係數 k = min(1, 人數 / 30)
魔王 HP × k、能量門檻 × k、大招傷害 × k
魔王攻擊力、隊伍血條、護盾  →  不縮放
```

> 為什麼攻擊力不縮放？因為隊伍血條是固定值。若攻擊力也跟著人數下降，
> 小班級的魔王就永遠打不死隊伍，遊戲會失去壓力。

**魔王攻擊力的推導目標：完全不答題的班級，會在時間結束前被打完。**

```
A × (時間 ÷ 攻擊間隔 ＋ 大招次數 × 大招倍率) = 隊伍血條 × 0.75
```

| 難度 | 時間 | 攻擊間隔 | 攻擊力 | 大招 | 不動作時的結果 |
|---|---|---|---|---|---|
| 簡單 | 5 分 | 14 秒 | 72 | 216 | 約 3.8 分鐘被打完（時間 5 分） |
| 普通 | 8 分 | 12 秒 | 40 | 120 | 約 6 分鐘被打完（時間 8 分） |
| 困難 | 10 分 | 10 秒 | 28 | 84 | 約 7.5 分鐘被打完（時間 10 分） |

護盾可吸收 **300** 點（約 7 次普通攻擊），讓防禦技能有實際價值。

> 所有數值都在 `src/config/gameDefaults.ts`，已標註「可調」。
> 魔王 HP 是依「30 人 × 每 12 秒答一題 × 65% 正確率」推導；
> 實際上課後建議再依班級狀況微調。

### 勝利／失敗樂句

不是用現成音檔，而是**用程式合成的約 5 秒樂句**（`src/lib/audio/index.ts`）：

- **勝利**：C 大調上行號角（C-C-C-E, E-D-E-F, G）＋小鼓滾奏＋鈸＋收尾大和弦（歡樂）
- **失敗**：A 小調下行嘆息（A-G-F-E-D-C）＋低沉小和弦（哀傷）

每個音都用鋸齒波＋方波疊加、低八度加厚，聽起來比單純的方波飽滿。
要改旋律直接編輯 `WIN_FANFARE` / `LOSE_FANFARE` 這兩個陣列即可。

## 結算與報表（M5）

戰鬥結束後，老師端與學生端都會自動切換成結算畫面。

**獎項（每項各取一名）**

| 獎項 | 依據 |
|---|---|
| 🏆 MVP | 綜合積分（傷害 50% ＋ 正確率 30% ＋ 連擊 20%） |
| ⚔️ 最強戰士 | 總傷害最高 |
| 🛡️ 最佳防禦手 | 防禦能量貢獻最高 |
| 🔥 大招功臣 | 大招能量貢獻最高 |
| 🎯 神射手 | 正確率最高（至少答 3 題） |
| ⚡ 快手 | 平均作答秒數最短（至少答 3 題） |
| 💥 連擊王 | 最高連擊數 |

**排行榜與統計**

老師端會看到全班排行；學生端只會看到自己的名次、成績與獲獎，以及前 5 名。

每位學生的統計包含：答對、答錯、總題數、正確率、總傷害、防禦貢獻、大招貢獻、
最高連擊、平均作答秒數。

**CSV 報表**

結算畫面按「⬇ 下載 CSV 報表」即可下載，欄位為：

```
名次, 座號, 姓名, 角色, 答對, 答錯, 總題數, 正確率,
總傷害, 防禦貢獻, 大招貢獻, 最高連擊, 平均作答秒數, 獲獎
```

檔名會自動帶上班級、難度與時間，例如 `五年一班_normal_20261104-0844.csv`。

**歷史紀錄**

每場遊戲結束後會自動存檔（最多保留 50 場），在老師端首頁可以：

- 看到每場的勝敗、班級、人數與時間
- 隨時重新下載該場的 CSV 報表
- 刪除單場紀錄或清空全部

讓學生知道現在發生什麼事。

### 一頁式投影版面

投影畫面鎖定 **100dvh、不允許頁面捲動**：戰場會自動吃掉剩餘高度，
底部是固定高度的血條與技能列，右側監控面板內部才可滾動。開會投影時**所有資訊都在同一個畫面裡**。

### 自適應縮放（不同電腦都能用）

全站根字級綁定視窗尺寸，**同時參考寬度與高度**並限制在 17～24px：

```css
html { font-size: clamp(17px, min(0.62vw, 1vh) + 10px, 24px); }
```

因為 Tailwind 的字級與間距都是 `rem`，整個介面會跟著解析度等比縮放：

| 螢幕 | 根字級 |
|---|---|
| 1366×768（舊筆電／投影機） | 約 17.7px（不會擠爆） |
| 1920×1080（常見 Full HD） | 約 20.8px |
| 2560×1440 / 4K | 約 24px（自動放大） |

角色尺寸也用 viewport 單位控制（`.scene-boss` 高 `clamp(190px, 38vh, 460px)`、
`.scene-hero` 高 `clamp(58px, 10.5vh, 124px)`），跟著視窗高度縮放，**寬度由素材比例自動決定**。
戰場內容用 flex 分左右（勇者直排靠左、魔王靠右），底部保留 `pb-16` 的空間，
所以大字幕出現時不會蓋住角色。

### 招式名稱

團隊技能的招式名稱定義在 `src/config/gameDefaults.ts` 的 `TEAM_SKILLS`，**可自由改成
自己班級喜歡的名字**：

| 技能 | 名稱 | 效果 |
|---|---|---|
| 🛡 防禦 | **聖光護盾** | 展開結界，魔王攻擊先被吸收 |
| ⚔ 大招 | **聖劍大審判** | 斬擊魔王並使其暈眩 |

**自動釋放**：開新遊戲時可勾選「能量滿了自動釋放技能」（預設開啟）。
開啟後能量集滿就會自動發動，**魔王大招快落下時會優先開護盾**。
關掉的話就要由老師手動按。

魔王也各自有大招名：史萊姆王「黏液爆發」、暗影法師「封印之霧」、魔王巴拉摩斯「滅世烈焰」。

### 動態角色（spritesheet）

角色是 Ninja Adventure 的**像素 spritesheet**，由 `src/components/SpriteActor.tsx`
顯示（`src/components/AnimatedHero.tsx` / `AnimatedBoss.tsx`）。

- **魔王**：Idle／Attack／Hit 圖是**真正的逐格動畫**，用 CSS `steps()` 循環播放。
- **勇者**：Idle／Attack 圖單列 4 格其實是**四個面向**（下／上／左／右），不是動畫，
  所以**固定顯示正面那一格**（`animate={false}`），改用 CSS 讓它呼吸／突刺──
  否則看起來會像在原地轉圈圈。

| 動作 | 觸發時機 | 表現 |
|---|---|---|
| `idle` 待機 | 平時 | 側面朝右站立，輕輕上下呼吸 |
| `attack` 攻擊 | **該職業有學生答對時** | 向前突刺（＋畫面交叉斬擊特效） |
| `cast` 施法 | 老師釋放護盾／大招時 | 待機 + 金色發光 |
| `hurt` 受擊 | 魔王被打到時／學生答錯時 | 紅閃 + 震動 |
| `down` 倒下 | 魔王被擊敗時 | 灰暗傾倒 |

播放原理：把整張橫向大圖放大 `frames` 倍塞進一個 `overflow: hidden` 的框，
再用 `transform: translateX()` 以百分比逐格平移。因為是百分比，**外框尺寸可以隨視窗自適應**，
不必在 CSS 寫死像素；配合 `image-rendering: pixelated`，放大後仍保持銳利的像素邊緣。
一次性動作以 `key` 強制重播，並用 `steps(frames-1)` + `fill: forwards` 停在最後一格。

| 時機 | 特效 |
|---|---|

## 啟用雲端即時連線（Supabase，免費）

正式上課時學生要用手機連線，請改用 Supabase。**完全免費，不用信用卡。**

### 1. 註冊並建立專案

1. 前往 <https://supabase.com>，點 **Start your project**
2. 用 GitHub 或 Email 註冊登入
3. 點 **New project**
   - Name：`pixel-heroes`
   - Database Password：隨便設一組（本專案不會用到資料庫，但專案必須設定）
   - Region：選 **Southeast Asia (Singapore)**（離台灣最近、延遲最低）
4. 按 **Create new project**，等待 1～2 分鐘建立完成

### 2. 取得連線資訊

1. 左側選單 → **Project Settings**（齒輪圖示）→ **API**
2. 複製以下兩個值：
   - **Project URL** → 例如 `https://abcdefgh.supabase.co`
   - **anon public** key（在 Project API keys 區塊）

### 3. 填入環境變數

在專案根目錄建立 `.env.local`（可從 `.env.example` 複製）：

```
VITE_SUPABASE_URL=https://你的專案.supabase.co
VITE_SUPABASE_ANON_KEY=你的_anon_key
VITE_REALTIME_MODE=auto
```

存檔後**重新啟動** `npm run dev`。打開「老師控制台」（`/teacher`），右上角會顯示
**☁ Supabase（雲端）**；若顯示 **🖥 本機模式**，代表環境變數沒讀到（學生手機將無法連線，
畫面上也會出現紅色警告）。

> 小提醒：後台有兩個很像的網址。請用 **Project URL**（`https://xxx.supabase.co`）。
> 如果不小心貼到 **Data API URL**（結尾多一段 `/rest/v1/`），程式會自動修正，
> 不影響運作。

> `anon` key 是設計給前端公開使用的，寫在前端沒有問題。
> 本專案不使用資料庫，因此沒有資料外洩疑慮。

### 4. 免費方案注意事項

- Supabase 免費專案若**連續 7 天沒有使用**會被自動暫停。
  上課前若發現連不上，到 Supabase 後台點一下 **Restore / Resume** 即可（約 1 分鐘）。
- 免費方案同時支援 200 條即時連線，一班 30～40 人非常充裕。

## 加入驗證的設計（重要）

老師端是唯一權威，且**判斷結果是確定性的**：老師端直接從 Presence 名單推導
「誰成功加入、誰被拒絕」，而不是自己記一份狀態。這代表老師端重新整理後，
名單依然正確。

驗證規則依序為：

1. 同一個座號只取最早加入的連線，其餘視為重複並拒絕
2. 有設定名單時，座號必須在名單內
3. 人數不得超過上限
4. 遊戲已開始且不允許中途加入時，只接受「開始前就在場的座號」

## 名詞與縮寫

- **Presence**：即時服務提供的「誰在線」狀態
- **Broadcast**：即時服務提供的訊息廣播
- **Host Authority**：老師端是唯一權威，所有共享數值由老師端計算並廣播
